# Student Performance Analytics Dashboard

An end-to-end analytics project: **Oracle SQL → Python → Power BI**. It turns raw student marks and attendance into a two-page dashboard that shows how departments compare against targets and which students need attention.

> **Important: this project uses simulated (mock) data.** The 1,000 students, their marks and their attendance were generated by a script (`generate_mock_data.py`, seed 42). Department averages were deliberately set to differ slightly. The targets (70 marks, 75% attendance) and the "near target" band (within 2 marks) are **assumptions I chose**, not real institutional standards. Findings below describe this simulated dataset only.

## Key findings (simulated data)

| Metric | Result |
|---|---|
| Students | 1,000 across 6 departments (CSE, IT, ECE, EEE, Mechanical, Civil) |
| Average marks | 71.5 (assumed target 70, so +1.5) |
| Highest / lowest department | CSE 75.8 / Civil 65.8 |
| Average attendance | 86.3% (assumed target 75%, so +11.3 points) |
| At-risk students (attendance below 75%) | 57 students (5.7%) |
| Top performers (grade A+ or A) | 17.0% of students |
| Highest / lowest individual average | 95.0 / 42.5 |

Departments are classed as **Above target** (0 or more vs target), **Near target** (within 2 marks below) or **Below target**. In this data, CSE, ECE and IT are above target, EEE is near target, and Mechanical and Civil are below target.

## What each visual answers

| Visual | Question it answers |
|---|---|
| KPI cards (students, avg marks, avg attendance, at-risk, top performers %) | How are we doing overall? |
| "vs Target" cards (green/red) | Are marks and attendance above or below the target? |
| Avg Marks by Department vs Target (columns + target line) | Which departments are above or below the marks target? |
| Avg Attendance % by Department vs Target | Which departments are above or below the attendance target? |
| Department Scorecard (status + recommendation) | Which department needs attention, and what should be done? |
| Key Insights box | What do the numbers mean in plain words? |
| Top 10 / Bottom 10 students | Who are the strongest and weakest students by average marks? |
| At-Risk Students list | Which students have attendance below 75%? |
| Department slicer | Show me only one department (filters every visual) |

## Pipeline

```
Oracle SQL (schema.sql)  →  Python (pandas)  →  5 CSV reports  →  Power Query  →  Data model  →  DAX  →  Dashboard
```

1. **Oracle SQL:** four related tables (STUDENTS, SUBJECTS, MARKS, ATTENDANCE) with primary and foreign keys. Row counts: 1,000 / 15 / 6,000 / 1,000.
2. **Python:** runs SQL queries with joins and aggregation, assigns grades, and exports five CSV reports (student performance, attendance, grades, top students, summary statistics).
3. **Power Query:** sets data types, adds a `GRADE_ORDER` column so grades sort A+ to FAIL instead of alphabetically, and builds a `Dim_Student` table of unique students.
4. **Data model:** a star-style design with `Dim_Student` as the hub, linked one-to-one on `STUDENT_ID` to the performance, attendance and grade tables. One department slicer filters everything.
5. **DAX:** measures for the KPIs, targets and the status and recommendation logic.

---

## DAX measures used

- `Total Students`, `Avg Marks`, `Avg Attendance %`
- `At-Risk Students` (CALCULATE with an attendance filter below 75)
- `Top Performers %` (CALCULATE + DIVIDE, grades A+ and A)
- `Marks Target`, `Attendance Target`, `Marks vs Target`, `Attendance vs Target`
- `Marks % of Target`, `Marks Status` and `Marks Recommendation` (SWITCH)

## How to run

1. Run `schema.sql` in Oracle SQL Developer (Run Script, F5) to create and fill the tables.
2. Run `report_generator.py`. It asks for your database password when it starts, so no password is stored in the code. Update the user and connection details at the top of the file for your own database.
3. Open `Claude_Project.pbix` in Power BI Desktop. If the CSV paths differ on your computer, change them under **Transform data > Data source settings**.

---

## Limitations

- All data is simulated, so no conclusion applies to real students.
- Targets and the at-risk threshold are assumptions, and different thresholds would change the at-risk count.
- The dataset has no dates, so there are no trend charts.
